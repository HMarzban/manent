A budget is met only when the whole interval lies at or under it, and missed only when the whole interval lies over it; an interval that crosses a limit is undecided. A percentile is decided only over enough samples: 10 for p50, 40 for p95 and 200 for p99, and for keystrokes and frames at least 200 kept in each process, after the first tenth of each process's samples (at least 20) is dropped as warm-up. A timing budget needs at least five processes. A figure with one value per process, a size and a count are compared directly with their limit. A budget is judged only on the tier named for it, at 1x and outside a quick run; every other run is reported and not judged.

Before each scenario the runner checked that the machine was quiet: a one-minute load average at or under a quarter of the cores it sees (at least 1), and a fixed calibration loop whose 90th-percentile time was at most 1.25 times its 10th. It checked every 5 seconds for up to one minute; a scenario that never found the machine quiet is reported as void, with what the check saw.

## Limits of the method

1. A container's processor limit gives a fast core in bursts, not a slow core, so typing is also measured with Chromium's processor slowdown at 4 and 6 times.
2. The slowdown stretches the page's own JavaScript, style and layout on its main thread. It does not slow the browser's other processes, the network, the disk, memory bandwidth, the server or the sync path, and it does not model a slower graphics card or a hot laptop that lowers its clock. A 4x figure is a bound for script cost on a slower processor, not a prediction for any one laptop.
3. Containers have no graphics card, so paint times read worse than on a real machine.
4. Docker runs Linux only. Windows is checked on shared CI machines for whether the app works, never for timing; macOS is measured directly on one Apple-silicon laptop, the host tier. Processor emulation is never used for timing.
5. Server figures come from the D-small container, where the simulated clients share the server's one core, so they read worse than a server alone would.
6. Headless browsers have no spellchecker, so spellcheck is measured in headed Chromium with a virtual display.
7. Simulated: writers and readers at the rates of the profiles above, generated scripts and prose, and offline hours compressed into seconds. Not simulated: real typists, real networks with loss and delay, and browsers other than Chromium, Firefox and WebKit.
8. The power-loss model copies files while writing and models a cut that keeps what reached the file system, not the disk's cache.

## Limits to state first

1. The 2,000-page length is a target, not a promise. The measured comfort limit of each tier stands in its place: not measured.
2. A project can hold thousands of documents and any number of versions, because neither is loaded with the script being edited.
3. Offline storage in a browser is kept at the browser's discretion; the desktop app is the durable offline client.
4. Who wrote each character is kept character by character only since the newest checkpoint; older versions record it per block.
5. Characters outside the script font are kept, but not typeset or printed correctly.
6. The half of the wrong design that keeps thousands of versions inside the live document cannot be built here, so it is not measured and no figure is given.

## Past the comfortable length

The app shows one notice, on every device, once a script passes 120 pages: '&lt;title&gt;' is longer than this device handles comfortably, so typing may slow down. That figure comes from one reference machine. The measured comfort limits are: not measured. A slower device slows down before it is told; a faster one is told early.

## Where it breaks

| Mechanism                                     | Cause                                                                                   | Solution adopted                                                                                               | Rows                                         |
| --------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| The editable page grows with the script       | Every block is an element the browser keeps and lays out                                | The script is split into sections of about 100 blocks, and the browser skips the layout of sections off screen | not measured                                 |
| Remote changes cost the whole document        | Each remote change replaces the editor's whole document                                 | Remote changes are merged into one update per frame                                                            | not measured                                 |
| Writer identities pile up with sessions       | Each editing session adds a writer identity to the document, and the list never shrinks | The document is rebuilt once it passes a size or identity budget                                               | not measured                                 |
| History inside the live document              | Every kept version would make the live document larger                                  | Versions are kept outside the live document                                                                    | history.list.first_page, history.restore.120 |
| A join storm encodes the room for each client | Each joining client asks for the whole state                                            | The state is encoded once for all the clients that join together                                               | not measured                                 |

## Trade-offs

| #   | Trade-off                                                                                | What we gain                                                                                                        | What we give up, and where the limit is                                                                                                                                                                                                                                                                                                                                                                                                                           | Rows that bear on it                            |

| 1   | CRDT instead of a central authority                                                      | Offline edits of any age merge without dropping steps                                                               | For an online-only product an authority model is simpler and would be the better pick. | 2   | Rebuilding a document when it is over budget                                             | Typing cost and size stay flat however long a show runs                                                             | Every rebuild turns later offline arrivals from a character-level merge into a block-level replay and resets undo.
