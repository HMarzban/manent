# Workspace, search and Ink

How Manent indexes workspaces for full-text search, organises folders, Favourites, Private scripts and recoverable Trash, resolves workspace settings and "Can also" permissions, serves the public REST API and outbound notifications, hosts Ink compilation and playback, pins layout engine versions and writes production Sides on top of [overview.md](overview.md).

## Full-text search

Search is backed by a derived SQLite index (`search.sqlite`) sitting beside the authoritative document files, accessed strictly through the `SearchIndex` port in `packages/storage/src/ports/search.ts` ([decision 0060](../decisions/0060-derived-search-index.md)).

- **Derived FTS5 schema:** `packages/storage/src/search/sqlite.ts` stores `PRAGMA user_version = SEARCH_INDEX_VERSION`. Whenever the stored version differs from the build's version, the schema is dropped and recreated cleanly so an older index never blocks startup. Full-text matching uses FTS5 with the `unicode61` tokeniser across document titles, script body text, notes, cuts (`cuts-extractor.ts`) and rundown cells (`rundown-extractor.ts`).
- **Asynchronous catch-up indexing:** `createSearchService` (`packages/server-core/src/search/service.ts`) listens to committed document updates and runs an asynchronous catch-up pass off the write path, extracting committed text without delaying keystroke commits or room acknowledgements.
- **Query parsing and access filtering:** `GET /api/search` parses free words, quoted phrases and structured filters (`type:`, `folder:`, `after:`, `before:`) through `packages/server-core/src/search/query-parser.ts`. Candidate matches are filtered against the caller's live directory roles, excluding trashed documents, tombstoned documents and any script in another person's Private folder.
- **Browser offline fallback, desktop offline search and palette search:** in `apps/web`, Library search runs against `GET /api/search` with a Filter menu and highlighted `<mark>` excerpts while online, and falls back to title-only matching over synced local workspace metadata when offline or refused. The desktop local node (`packages/local-node/src/search/`) runs full-text FTS5 indexing offline across authority and relayed documents. The command palette shows immediate local title matches and appends asynchronous server body matches without reordering rows already on screen.

## Folders, Favourites, Private folder and Trash

- **Workspace folders:** nested folders live in the workspace index's `folders` map (`{ name, parentId, createdAt, createdByUserId }`), and each project entry in `projects` carries an optional `folderId` ([decision 0063](../decisions/0063-folders-in-workspace-index.md)). Folder trees are read directly from the syncing workspace index and fed into search metadata so `folder:` queries match nested sub-folders as well.
- **Favourites and Private folder:** each person's private index (`indexDocId("user", userId)`) keeps their `favourites` map (keyed by project or document ID with `{ kind, workspaceId, favouritedAt }`) and their `private_folder` map for personal scripts outside shared workspaces. Both sync across that person's own devices and never leak into workspace indexes, workspace search for other members or the public API.
- **Recoverable Trash:** `createTrashService` (`packages/server-core/src/library/service.ts`) implements `POST /api/trash/move`, `POST /api/trash/restore` and `POST /api/trash/list` backed by the `trash` table in `control.sqlite` ([decision 0062](../decisions/0062-recoverable-trash.md)). Moving a script to Trash stamps `trashedAt` and `trashedByUserId` in its index and sets `purgeAfter = deletedAt + 30 days` on the server clock (`TRASH_KEEP_MS`). An hourly sweep tombstones expired rows and removes their index entries. Edits already in flight or made to a trashed script are kept, and offline devices preserve local copies cleanly until restored or purged.

## Workspace settings and "Can also" permissions

- **Workspace settings:** `packages/server-core/src/workspace/` serves workspace metadata, owner-only workspace renaming, member listing, role updates, owner transfer and member removal, with a sign-out guard in `apps/web` that checks for unsent local edits before clearing a session.
- **"Can also" capabilities:** each project index holds a `can_also` map storing explicit per-capability grants (`{ userIds, groupIds }`) for `issue_revisions`, `lock_page_numbers`, `edit_rundowns`, `send_to_prompter` and `delete` ([decision 0064](../decisions/0064-can-also-project-permissions.md)). `capabilitiesOf` (`packages/server-core/src/permissions/capabilities.ts`) resolves effective capabilities from the project index's `can_also` map (replacing legacy `doc_roles` capability rows for covered keys), while `can-also-rule.ts` limits pushes touching `can_also` to workspace or project owners and people authorised to issue revisions.

## Public REST API and outbound notifications

### Public API

`createPublicApiService` (`packages/server-core/src/public-api/service.ts`) serves four read-only HTTP routes under `/api/v1/`: `GET /api/v1/folder`, `GET /api/v1/lines`, `GET /api/v1/fdx` (clean Final Draft XML with `production: null`) and `GET /api/v1/ink` (compiled Ink story JSON), documented for callers in [../guide/api.md](../guide/api.md).

- **API-key-only authentication:** every `/api/v1/` request requires `Authorization: Bearer mk_…`; user session tokens are always refused with `401` ([decision 0065](../decisions/0065-public-api-auth-and-scope.md)). Keys are created and revoked by workspace owners in Workspace settings → API keys, shown once at creation time, and stored in SQLite solely as SHA-256 hashes.
- **Per-key rate limiting and strict workspace scope:** `createKeyLimiter` (`packages/server-core/src/public-api/key-limits.ts`) enforces a token bucket of 1 request per second sustained with a burst of 30 per key, answering `429` with whole-second `Retry-After`, and drops the bucket immediately upon revocation. `packages/server-core/src/public-api/scope.ts` corroborates every folder and document lookup against server-held directory state, refusing Trash, Private (`user:` homes), tombstoned documents and cross-workspace references with `404`.

### Outbound notifications

`createNotificationsService` (`packages/server-core/src/notifications/service.ts`) delivers comment notifications (`thread_opened`, `reply_added`, `person_mentioned`) for live workspace scripts—never for Private (`user:`) documents—to owner-configured Webhook, Slack (`https://hooks.slack.com/…`) or Resend email destinations ([decision 0066](../decisions/0066-outbox-notifications.md)).

- **Outbox off the write path:** comment commits enqueue rows into SQLite outbox storage and return immediately. A background delivery loop drains due rows with a 10-second per-attempt timeout and fixed retry backoff of 1, 5, 30, 120 and 720 minutes, stopping after 6 tries.
- **Secrets and configuration:** saved destination addresses are never sent back in full after saving; Workspace settings displays only server-masked hints (`<host>/…<last4>` or `…@<domain>`). Email delivery requires both `MANENT_RESEND_API_KEY` and `MANENT_RESEND_FROM` in the server environment (`apps/server/src/env.ts`) and sends to one owner-chosen address; stored outbox rows hold only the subject and text body, never credentials. Slack delivery is built against its public API and has not been verified against a real Slack workspace.

## Ink compile host, player and Game Script exports

- **Dedicated Web Worker host:** in the browser, `apps/web/src/ink/compile-client.ts` debounces Ink source changes over 150 ms with a single queued follow-up and runs both `compileInk` and the live `InkStory` runtime inside a dedicated classic Web Worker (`apps/web/src/ink/compile.worker.ts`) precached by the service worker, retaining the compiler beside the runtime so 1-based source line numbers survive compilation ([decision 0061](../decisions/0061-ink-compile-and-player-host.md)). Non-browser unit tests fall back cleanly to the same handler in process.
- **Problems, live player Beside and shared Ink Reader Player:** compilation diagnostics draw inline squiggles and clickable problem links that jump directly to the source line. Play and Play from here open an interactive Ink player in the Beside slot (`apps/web/src/ink/player/`) with choice replay across live recompiles, last-good fallback while source does not compile, visited line marks in the editor gutter, per-person playthrough persistence (`manent.ink.<userId>`) and a live Variables drawer. Shared Ink drafts sent to external readers (`/r/<token>`) render a standalone full-window interactive Ink Reader Player (`apps/web/src/screens/reader/reader-ink-player.tsx`, `reader-ink-controller.ts`) with choices, keyboard shortcuts, Back, Restart, Variables drawer, watermark and offline cached playback. Game Scripts (`format === "game"`) share the same Play title-bar control and commands, backed by a pure block walker (`packages/schema/src/game-playthrough.ts`) and `game_player` Beside pane (`apps/web/src/game/player/`) supporting scene switching, nested choices and gathers, `#set` flags, `{condition}` gates (plus manual toggles for custom expressions), toggleable Emote/Camera/Engine cues and click-to-block navigation ([decision 0085](../decisions/0085-game-script-playthrough-and-unified-player.md)).
- **Ink and Game Script exports:** `packages/formats/src/` exports whole Ink projects as one concatenated `.ink` file in Library order with title comments ([decision 0071](../decisions/0071-whole-ink-project-export.md)), compiled Ink story JSON, and Game Script Line data in JSON and XML (character, dialogue, stable block ID, tags, scene and conditions).

## Writing tools, layout engines and production Sides

- **Writing tools:** `packages/revisions/src/numbers/` computes Script numbers (pages, scenes, estimated runtime at one minute a page, eighths when locked and dialogue counts by character), near-duplicate location Checks and Animation Pickup lines (dialogue changed since the newest draft named `Record`, exported as CSV; [decision 0069](../decisions/0069-animation-pickup-lines.md)). `packages/formats/src/reports/` writes character, scene and location reports in both RFC 4180 CSV and Courier Prime PDF ([decision 0070](../decisions/0070-script-reports-csv-and-pdf.md)). The web app adds single-undo Rename character, Focus mode hiding both panels with per-device persistence in `PlaceStore`, browser speech-synthesis Read aloud, and personal daily writing goals and timed sprints.
- **Layout settings and versioned engines:** `packages/pagination/src/engines/` carries versioned layout engines (`v1`, `v2`, and opt-in `v3` Book Publishing with bundled Source Serif 4 FUnit metrics, five paperback/manuscript trim sizes, mirrored recto/verso margins, shared running-header resolution with alternating `verso_title_recto_chapter` heads and default chapter-opening suppression, optional blind-folio blank verso pages for right-hand chapter starts, and lowercase Roman-numeral front matter + auto-generated Table of Contents; [decision 0087](../decisions/0087-book-phase-2-craft-epub-and-layout-engine-v3.md), [decision 0088](../decisions/0088-book-phase-3-publishing-matter-spreads-markdown-and-compile.md)) alongside `script.linesPerPage`, `script.lineSpacing`, `script.mirrorMargins`, `script.rectoChapters`, `script.includeToc`, `script.tocSubheadings`, `script.sceneNumbers` and `script.engineVersion` in `packages/settings/src/definitions/script-layout.ts` ([decision 0067](../decisions/0067-explicit-layout-engine-pinning.md)). Every script stays on its pinned engine version (`1` when unset) until an editor explicitly chooses Update layout engine (or turns on **Book layout** in the floating Book Format Bar on a manuscript) before locking, preventing silent page-break drift across builds.
- **Production Sides:** `packages/revisions` resolves chosen scene ranges onto locked page indices, and `packages/formats/src/production/sides.ts` writes whole locked pages with their locked page labels and unselected scenes' lines struck through ([decision 0068](../decisions/0068-sides-export-format.md)), launched from Export → Sides or a scene's row menu ("Include in sides…").

## Known limits

- Offline search in the browser matches synced local titles only; full-text offline FTS5 search runs in the desktop local node.
- Slack notifications are implemented against Slack's public incoming-webhook format and have not been verified against a real Slack workspace.
- Standard `D-modest`/`D-typical`/`host` benchmark runs, search indexing benchmarks and modest-hardware runs remain to be published in [../benchmark/report.md](../benchmark/report.md).
