# Changelog

What changed in Manent, newest first, written for a reader who did not see the work. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). No release has been made yet, so every entry is under Unreleased. Each entry begins with the day it reached `main`.

## [Unreleased]

### Added

- 2026-11-18 — A README that says exactly what runs today, and three architecture pages in `docs/architecture/`: an overview with the status of every part, the dependency rules as they are enforced, and an outline of the repository with its commands. The gate now compares the overview's package table with the source folders and requires every link between public documents to lead to a tracked file.
- 2026-11-18 — Project records: this changelog, decision records in `docs/decisions/`, lessons in `docs/memory/lessons.md` and the standing rules in `AGENTS.md`. The README acknowledges the project's inspiration and points to the licence, in two sections whose text is fixed. `bun run verify` now checks that the records keep their format, that every decision record is numbered, indexed and has a valid status, that the README's two fixed sections are unchanged, and that no public document names anything kept out of the repository.
- 2026-11-18 — The demo starts with `make demo` and is managed with `make reset` and `make stop`: `tools/demo/` checks the machine first, keeps the server running under a supervisor process that starts and stops it, and seeds the demo people and four empty workspaces from `@manent/demo`. `@manent/crdt` creates documents with garbage collection on, writes to blocks by ID and applies an update completely or not at all, and the server opens the sync socket to a client that presents a single-use ticket, and both sides agree on versions in a handshake. End-to-end tests run the demo in Chromium, Firefox and WebKit, a fresh-clone test starts it from a new copy of the repository, `bun run tour` checks that every Tour scenario has its test, the README fits one screen, and `.github/workflows/ci.yml` runs the gate and both test suites on Linux, macOS and Windows.
- 2026-11-18 — The boundary rules are one table, `RULES` in `tools/boundaries.config.ts`, with a row for every workspace in six layers, path-scoped zones, rules for test code and a size limit for source files; five new, empty packages (`settings`, `commands`, `client-web`, `crdt-binding`, `demo`) and a registration list in each package that many changes will write into. Every dependency the coming work needs is declared now with an exact version, the HTTP route bodies are shared types in `packages/sync-protocol/src/http.ts`, and the wire format had its last round of changes (message IDs per connection, nested structures behind their length, a request to change a script setting) before it was frozen again. The schema gained one canonical JSON form and a plain-data list of a document's blocks, the demo people, the demo sign-in and the Tour moved into `@manent/demo`, and performance marks read an injected clock.
- 2026-11-17 — The terms on which Manent may be used are in `LICENSE`.
- 2026-11-17 — `@manent/sync-protocol`: the wire messages, a binary frame codec, chunking of large messages and version gating, pinned by fixed bytes for every frame type. A frame type, flag or trailing field that an older build does not know is skipped, never refused. Nothing uses the protocol yet.
- 2026-11-17 — `@manent/schema`: a document is a list of sections that hold blocks, with one block node whose element is an attribute, and the elements and marks of every format. Every block keeps a stable ID under rules for splitting and joining; `validateDoc` sorts what it finds as `repair`, `reject` or `newer`, and `normalizeDoc` makes the repairs any client may make.
- 2026-11-17 — `apps/web`: the "Choose who you are" screen, an empty Library and the demo bar, built by `apps/web/build.ts`. Each browser tab keeps its own person, so two tabs can be two people. The Tour, the guided walk through the demo, has a file format and a validator.
- 2026-11-17 — `@manent/perf`: timing marks that record nothing until they are switched on, and the benchmark harness in `bench/`, run with `bun run bench`. The budget file `bench/budgets.json` is validated before a run, so a malformed row stops it; there are no scenarios yet.
- 2026-11-17 — `@manent/server-core` and `apps/server`: the demo sign-in provider and its sessions, and the routes `GET /health`, `GET` and `POST /api/sign-in`, `GET /api/me` and `GET /api/demo`. The server will not listen on an address outside loopback and the private ranges, answers only requests addressed to its own host, and serves the built web app.
- 2026-11-17 — `bun run boundaries` (`tools/check-boundaries.ts`) refuses an import that the allow-list in `tools/boundaries.config.ts` does not permit, a deep import into another package, a Bun or Node module in a package that runs in a browser, and a browser or Bun global in a pure package. It is a step of `bun run verify`, the one gate, beside `bun run tracked`, which accepts only the files on the allow-list of the public tree in `tools/check-tracked.ts`.
- 2026-11-17 — A Bun workspace with one version catalog in the root `package.json`, fourteen packages and three apps as empty entries, `make` targets that wrap `bun run`, LF line endings on every system (`.gitattributes`), and a rule in `bunfig.toml` that a release must be three days old before it is installed.
